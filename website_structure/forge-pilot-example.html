Worked FORGE pilot example

One workflow, installed around real commercial work.

This is an anonymised example, not a client case study. It shows what FORGE can switch on first, what the team retains and what evidence a bounded pilot should produce.

Explore the example ↓How FORGE works
The boundary

No invented win rate or time-saving claim.

The example defines what would be measured. Any benefit claim would come from the pilot evidence, not from a demonstration.

The workflow

See the sell-side pilot and its buy-side twin.

The two routes use the same operating model. The source material, first workflow and retained human decisions are different.

01 / Trigger

The ITT lands.

The team opens a controlled project folder and confirms the source package and deadline.

02 / Structure

Requirements are extracted.

FORGE builds the compliance and response matrix with source references and mandatory checks.

03 / Ownership

Work is allocated.

Every requirement receives an owner, status and evidence need. Gaps become visible early.

04 / Assurance

Responses are checked.

The team sees completeness, citation coverage, exceptions and work awaiting a decision.

05 / Learning

Useful evidence returns.

Approved content and lessons can be reviewed for reuse in the next pursuit.

People retain

Go / No-Go, commercial strategy, exceptions, final response judgement and submission sign-off.

Matrix completenessAre all requirements captured and owned?
Citation coverageCan material claims be traced to trusted sources?
Time to first ownerHow quickly is each requirement allocated?
Gate outcomesAre required decisions made with visible evidence?
01 / Trigger

Supplier returns arrive.

The team confirms the controlled return set, evaluation rules and decision timetable.

02 / Structure

Returns become comparable.

FORGE builds one evaluation matrix and identifies mandatory checks and missing evidence.

03 / Clarify

Gaps are handled consistently.

Questions, responses and changes remain visible under the agreed equal-treatment protocol.

04 / Evaluate

Evidence supports judgement.

Evaluators see source-linked responses and exceptions without delegating scores to an agent.

05 / Learning

The sourcing record endures.

Approved rationale and lessons can be carried into the next tender cycle.

People retain

Scoring judgement, clarification decisions, moderation, commercial exceptions and the award decision.

Evaluation completenessAre all criteria and returns covered?
Mandatory checksAre pass/fail requirements evidenced?
Clarification controlIs equal treatment visible in the record?
Decision traceabilityCan the award rationale be reconstructed?
What is installed

A small operating system for one project.

The pilot is configured as a plugin in the team’s approved AI environment and project folder. It includes the workflow instructions, controlled templates, naming and status rules, human gates and review measures needed to run the chosen spine.

The rest of the practice map stays off. New workflows are only connected when the pilot evidence justifies them.
